# ONLYOFFICE blog

WordPress backend of blog.onlyoffice.com, shipped as the Docker image `onlyoffice/blog`.

## What goes into the image

The image is built on the official `wordpress:<version>-php<version>-apache` image (see `Dockerfile`).
WordPress core and `wp-config.php` come from the base image; this repository provides only:

- `wp-content/` — themes, plugins, `object-cache.php` drop-in source
- `health.php` — probe endpoint (no WordPress bootstrap, no DB)
- `apache-mpm-prefork.conf` — Apache MPM tuning

Files must be copied to `/usr/src/wordpress/`, not `/var/www/html/`: the base image entrypoint
copies `/usr/src/wordpress/` into the docroot on every container start.

`wp-config.php` is generated by the entrypoint from `WORDPRESS_*` environment variables
and must not be committed.

## Updating WordPress / PHP

Bump the `FROM` tag in `Dockerfile`. Use a full version tag (`7.1.5-php8.4-apache`):
upstream does not rebuild old version tags, so PHP security fixes arrive only with a newer
WordPress tag. After deploy, check `php -v` and `wp-includes/version.php` in the pod.

## Build and release

Pushing a tag `X.Y.Z` runs `.github/workflows/build.yaml`: builds `onlyoffice/blog:X.Y.Z`
(linux/amd64), pushes it to Docker Hub and triggers the Flux webhook for the test stand.
Production is updated separately via the Flux repository.

## Notes

- Plugin auto-updates are disabled; plugins are updated only through this repository.
- `wp-content/plugins/urvanov-syntax-highlighter` contains a local patch (batched post scan);
  keep it when updating plugin files.
